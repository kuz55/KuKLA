# Security Policy

## Supported versions

KuKLA is under active development. Security fixes should target the current `main` branch unless a maintainer specifies otherwise.

## Reporting a vulnerability

Please do **not** disclose an unpatched security vulnerability in a public Issue.

If the repository's GitHub Security Advisories feature is available, use it to report the vulnerability privately. Otherwise, contact the project maintainer through the private contact channel listed on the GitHub profile.

Please include:

- affected component;
- vulnerability description;
- reproduction steps or proof of concept, when safe to provide;
- potential impact;
- suggested mitigation, if known.

Please do not include real personal data, real search-operation data, live credentials or real search coordinates in a report.

## Security expectations

KuKLA may be used to coordinate activities where incorrect data or unauthorized access can have serious consequences. Security issues involving authentication, authorization, GPS/location data, API access, data isolation, backups and offline synchronization should be treated as high priority.

KuKLA is not currently a certified mission-critical rescue system. Operational deployments must perform their own security assessment and hardening.
