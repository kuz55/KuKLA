# Учебный стенд — первая вертикальная часть

**Только вымышленные данные, доверенная локальная сеть и отдельная VM. Не для реальных поисков, персональных данных или публикации в интернет.** Учебный интерфейс частично покрывает сценарий от входа и обращения до результата задачи и закрытия поиска. Это ещё не готовый учебный релиз: управление полным составом, SMS, карта, офлайн, доставка уведомлений и сквозное ручное испытание не реализованы. Это временная браузерная оболочка, а не замена Windows-клиента.

## Изоляция и запуск

Для тестовой Debian VM выполните предварительные требования `docs/TRUENAS_LAN_TEST_RU.md`: выделенная VM, сетевой экран, отсутствие переадресации порта, Docker/Compose, проверенный тестовый CA. На сервере и клиенте — только синтетические данные. Перед запуском убедитесь, что старый стенд остановлен: оба занимают порт 18443. Не запускайте команды на хосте TrueNAS.

Из корня проверенной ветки:

```sh
cd infrastructure/lan-test
# Только если .env и private ещё не созданы: IP самой VM, не TrueNAS.
./init-test.sh 192.168.0.90
# Если обычный тестовый стек запущен, остановить без удаления его тома:
docker compose -f compose.yml down
# Отдельный проект и отдельный том с базой kukla_training:
docker compose -p kukla-training -f compose.yml -f compose.training.yml up -d --build
# После готовности и миграций, ОДИН РАЗ для новой пустой базы:
./seed-training.sh
```

Адрес замените на действительный частный IPv4 VM. Используйте один и тот же `-p kukla-training` и оба файла при управлении этим стендом. В отличие от базового production-контура этот отдельный учебный сервер запускается в режиме `test` с экспериментальными флагами; production-поведение и ограничения кода не изменены. База отдельная, но сертификаты и секреты берутся из существующего `.env`/`private`: не переносите их в другую среду. Проектное имя отделяет тома; не подключайте к стенду существующую или рабочую базу. Пароль и ключи не отправляйте в чат.

Скрипт создаёт семь учебных пользователей и необходимые тестовые допуски **только в пустой базе с именем `kukla_training`**. Пароли генерируются случайно и пишутся в `private/training-accounts.json` с правами владельца. Не пересылайте файл и не размещайте его в Git. Скрипт откажется перезаписывать его или заполнять непустую базу. Если запись файла или выполнение прервалось после фиксации транзакции, не запускайте повтор вслепую: проверьте состояние отдельной базы. Эти вымышленные пользователи не являются безопасным production-bootstrap.

На выделенной Windows-учётной записи установите **только тестовый CA** после сверки отпечатка, как описано в `docs/TRUENAS_LAN_TEST_RU.md`, и откройте `https://<IP-VM>:18443/`. После испытаний удалите доверие CA. Не отключайте проверку TLS. При ошибке доступа проверьте сеть и сертификат без передачи паролей или сырых логов.

Остановка без удаления базы:

```sh
docker compose -p kukla-training -f compose.yml -f compose.training.yml down
```

Не используйте `down -v`: это удалит том учебной базы. Копирование и восстановление тома отдельно ещё требуется проверить; не считать этот стенд проверенным резервным копированием.

## Что можно попробовать сейчас

1. Войти с учётной записью `operator` из файла. Заполнить **вымышленное** обращение; пустое поле означает «неизвестно». Создать и передать регистратору. SMS не отправляется.
2. Войти как `registrar`, обновить очередь, открыть карточку и создать поиск. Передать его ID учебному координатору и записать для назначения старшего.
3. Войти как `coordinator`, вставить ID и принять поиск. Если его уже принял другой координатор, интерфейс показывает ID ответственного и не утверждает, что назначил второго.
4. Войти как `fieldlead`, скопировать показанный учебный ID пользователя. Регистратор использует ID поиска и кандидата для предложения назначения. При ошибке связи регистратор не должен отправлять новое предложение вслепую: кандидат проверяет приглашения.
5. Под `fieldlead` обновить приглашения, проверить актуальность и принять. Уведомления надо открывать вручную, они не являются гарантированной доставкой. Повтор принятия возвращает историческую квитанцию, не подтверждение текущей должности.
6. Пока безопасное управление участниками поиска не готово, администратор **учебной VM** может вручную подготовить фиксированный набор из двух вымышленных участников к конкретному открытому поиску, созданному учебным регистратором: `./enrol-training.sh <ID-поиска>` и подтверждение `TRAINING`. Скрипт работает только с `NODE_ENV=test`, базой `kukla_training` и исходными учебными учётными записями `grouplead` и `searcher`, не выдаёт им управленческих ролей, не является пользовательским API и пишет отдельное событие учебной подготовки. Он не предназначен для эксплуатации. Повтор безопасен. Администратор не должен выполнять этот шаг для реальных данных.
7. Пользователь `grouplead` сообщает свой учебный ID. `fieldlead` создаёт группу с этим кандидатом; `grouplead` открывает приглашения и принимает. `fieldlead` назначает задачу со сроком и приоритетом, затем старший группы открывает список задач и принимает её. Срочные и просроченные задачи помечены текстом.
8. `grouplead` отправляет краткий вымышленный результат, используя ID задачи. `fieldlead` открывает историю результатов, принимает или возвращает с обязательной причиной. Возвращённый результат можно исправить повторной отправкой; задача считается завершённой только после приёмки.
9. `fieldlead` подтверждает готовность к закрытию. `coordinator` закрывает поиск, при исключительном закрытии без подтверждения вводит причину. SMS не отправляется. Повторное открытие требует причины; журнал проверяется отдельно. Закрытие и повторное открытие не имеют квитанции безопасного повтора: при ошибке связи не повторяйте действие вслепую, сначала проверьте журнал и состояние.
10. Другие пользователи не получают доступ к обращению только из-за наличия интерфейса: права проверяются сервером. На отказ интерфейс покажет сообщение. Передача ID между людьми — временное неудобство, а не готовый список поиска и участников.

Сетевой сбой при создании обращения, группы или задачи, а также отправке результата может произойти до или после записи. Не меняйте поля: повтор в той же открытой вкладке использует тот же ключ и те же данные. После обновления вкладки, выхода или закрытия браузера этот ключ теряется; офлайн-очереди нет, и повторное создание может привести к дублю. При неизвестном результате создания **поиска** интерфейс запрещает слепой повтор: откройте карточку заново и проверьте связанный поиск. Завершение сессии при недоступном сервере не подтверждено. Содержимое и сессия не сохраняются приложением на диск, но эта мера не защищает от браузерных расширений, ОС или других программ.

Автоматические тесты интерфейса используют имитацию API и не заменяют браузерную проверку HTTPS и многопользовательское испытание. Конфигурация Compose проверяется в CI, но после изменений стенда нужен новый ручной запуск; на момент написания он ещё не проводился.
